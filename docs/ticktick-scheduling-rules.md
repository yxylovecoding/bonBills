# TickTick 排任务规则

整理日期：2026-10-06。默认日期与调度时间采用北京时间（`Asia/Shanghai`）；任务自身的日期按其时区解析。

本文汇总 BonBills 当前实现、已保存的智能清单条件及 bon 在本次核查中明确的规则边界。智能清单条件来自项目在 2026-10-05 保存的记录；后续修改 TickTick 清单条件时，需要同步维护文档与相关筛选代码。本文中的“当前实现”不表示本次已修改排程程序。

## 1. 核心边界：空档补入只适用于普通任务

**“只要今天还有空档，就能把下一次任务提前拉到今天”仅适用于普通「今日事」，不能用于提前安排高优先级的「今天重要之事」。**

- 普通任务的优先级为无、低、中，对应 TickTick 数值 `0 / 1 / 3`。
- 重要任务的优先级为高，对应数值 `5`。高优先级表示重要程度，不意味着缩短重复周期。
- 例如「电动车充电」是高优先级任务，不参加普通任务的空档补入、挑选和延期。
- 高优先级任务仍可能因专门的场景、日期跟随、训练、洗衣或喷雾规则改期；必须按对应规则解释，不能归因于“今天有空档”。
- 普通轮换以“最久没做的优先”为首要规则，允许留空；不能在更久未做的可选任务仍因空档不足而等候时，用昨天刚完成的短任务填空。

## 2. 四个智能清单的范围

以下均为未完成任务，日期范围的末日包含在内。

| 智能清单 | 优先级 | 日期条件 | 排除标签 |
| --- | --- | --- | --- |
| 🍌今日事 | `0 / 1 / 3` | 今天 | `routine`、`bon-hidden`、`不关我事` |
| 🍌明日事 | `0 / 1 / 3` | 无日期、逾期或未来 1–30 天 | `routine`、`bon-hidden`、`不关我事` |
| ‼️今天重要之事 | `5` | 逾期或今天 | `routine`、`bon-hidden` |
| ❕明日之重要事 | `5` | 无日期或未来 1–21 天 | `routine`、`bon-hidden`、`不关我事`、`当天` |

「今天重要之事」有意没有排除 `不关我事`，不要把另三个清单的条件套用过来。`当天` 会排除未来重要事项的展示，但不会排除到期当天的重要事项；任务出现不必然意味着程序刚把它提前。

普通轮换代码在范围内还会处理逾期普通任务。智能清单显隐、场景改期与普通任务轮换是不同操作。

## 3. 场景标签先决定可执行日期

### `always-today` 固定今日截止日期

- 自身带 `always-today` 标签的未完成任务，截止日期始终随北京时间更新为当天；逾期、未来、无日期和仅有开始日期的任务均覆盖。移除标签后停止固定，已完成记录不修改，不向子任务隐式继承标签。
- 这是显式日期规则，优先于场景、重复周期、洗头跟随、训练、洗衣、喷雾错开及普通轮换。即使高优先级、带 `routine / bon-hidden / 不关我事` 或当天没有空档，仍保持今天；原显隐规则继续生效。
- 保留时刻、时区、起止间隔、提醒、其他标签、优先级和重复设置；无日期任务补全天日期，缺截止日期时补上。Checklist 沿用现有未完成有日期项调整规则。
- 复用云端零点显隐同步、每小时第 7 分钟核对和四次完整同步；凌晨隐藏期间及等待标签恢复时也维护日期，只暂停普通重排。GitHub Actions 可能延迟，实际更新发生在任务执行时。
- 可见的普通固定今日任务先预留当天耗时，高优先级任务沿用重要事项预算；普通轮换不能将其延期。

- 读取所有清单和收集箱中的未完成任务，使用任务自身的 `寄 / 居 / 旅` 标签；普通子任务不继承父任务标签。
- `寄` 对应父母家；`居` 对应日历的班、学；`旅` 对应旅行。旧标签 `寓` 按 `居` 处理，普通分类标签 `游` 不触发旅行排期。
- 从今天起查找最近的适用日，包含今天。`寄` 没有未来适用日时使用最近的春节兜底；`居 / 旅` 找不到适用日时保留原日期。
- 同时带多个场景标签时，比较有效候选日并取最近的一天。

### 长周期重复任务的当前实现

对于带 `居 / 寓` 或 `旅` 的长周期任务，每隔多天、每周、每月、每年及限定部分日期的非每日规则均按长周期处理：

1. 当前场景匹配任一自身标签，且已有日期：保留 TickTick 生成的下一次日期，包括逾期日期和对应 checklist 日期。
2. 离开所有适用场景：移到日历中最近适用场景的首日，**即使原日期更晚**。
3. 今天场景不明确、找不到未来适用日或无法解析重复规则：保留原日期。
4. 进入适用场景后，由 TickTick 按原重复规则继续循环；当天完成后生成的下一次长周期日期也保留。

这层场景同步没有统一排除高优先级任务。因此，“高优先级不参加空档补入”不等于“完整同步绝不修改高优先级日期”。仅带 `寄` 的任务不适用上述 `居 / 旅` 长周期日期保护，仍沿用最近场景日规则。

每日重复任务当天已完成时，从明天开始比较场景候选日，避免当天再次安排。

## 4. 普通任务的挑选与延期

### 候选范围

- 处理普通、未完成且不带 `routine / bon-hidden / 不关我事` 的任务。
- 已有日期不能超过未来 30 天；无日期及逾期普通任务也可参与。
- 今天必须符合任务自身的场景标签；今天不适用时，不因久未完成或剩余时间多而拉回今天。
- 固定时刻任务、无法解析的重复规则、出行与心愿模板树、洗头及洗头日期跟随项不参加普通轮换。训练和洗衣由专门逻辑管理。
- 同一个重复系列今天已经完成时，本次不再选入。

### 挑选顺序

1. 没有匹配完成记录的任务优先补齐轮换，不把创建或改期时间当作实际完成时间。
2. 有完成记录的任务按上次实际完成时间从早到晚挑选，即“最久没做的优先”。周期到期或自动改期不能让最近完成的任务插队。
3. 完成时间相同或都没有记录时，再比较紧迫程度：周期或原定截止日已到、没有下一适用场景日，或下一适用场景日晚于截止日的任务优先。
4. 最后按截止日、创建时间和任务 ID 确定稳定顺序；简报保留本轮实际挑选顺序。
5. 任务必须放入一个连续空档，并满足剩余额度与喷雾互斥规则。若更久未做的可选任务因空档不足而待安排，不用昨天刚完成的任务填空；没有后续适用场景而必须保留的今日任务仍可保留。

周期分摊值只用于说明，不限制本轮分钟数；可继续从「明日事」补入符合上述顺序与约束的普通任务，直到没有可安排候选，不要求凑满。

### 未入选任务

- 今天及逾期的普通任务未入选时，移到明天或下一个适用场景日。
- 未来或无日期任务未入选时，保留原日期，包括继续无日期。
- 当前任务没有后续适用场景日时可能保留在今天，并明确说明时间不足，需要手动协调。
- 延期不是完成，不能让原周期截止日跟着延期向后移动。

## 5. 时间预算与估时

- 自动预算依赖 Outlook 的实际空档。默认可用时段为 `09:00–11:00`、`14:00–18:00`、`20:00–22:00`。
- 所有模式均排除 `11:00–14:00` 的午饭与休息、`18:00–20:00` 的晚饭与休息。
- 可选仅晚间 `20:00–22:00`，或跟随日历并排除餐休。所有模式都不因「旅」等日期场景标记或 Outlook 全天日程扣减可用时间，也不自动预留 `09:00–18:00`；只按具体时刻的日程计算占用。任务自身的寄／居／旅适用范围及专项日期规则继续生效。
- 每轮从实际执行时刻裁剪当天时段，只使用尚未过去的时间；定时延迟也按实际执行时间计算。
- Outlook 与 TickTick 的具体占用时段取并集。同名且唯一对应的事项不重复扣时，重名歧义不猜配。
- 固定普通任务需要预留时间；已完成普通任务仍计入当日用量，防止完成后无限补入。
- 今日未完成的重要事项先占用剩余时间，再安排普通任务。未定时或已错过预约但未完成的事项按估时预留；已有尚未结束的唯一对应 Outlook 日程或 TickTick 定时区间时，只扣实际区间，不重复扣估时。重要清单按高优先级、逾期／今天及非 routine／bon-hidden 筛选，不排除「不关我事」。
- 页面直接使用同一轮后台保存的日程占用、重要事项扣除后剩余和新增额度，不在前端另扣一次重要事项。重要事项汇总显示本步实际扣除的时间；已被日程覆盖时显示另需时间。
- 多个碎片空档不能拼成一个长任务。没有额外休息缓冲，也不使用固定 30 分钟额度或按重要事项数量打折。
- 可保存 `10–240` 分钟的手动每日上限；上限仍受当天实际剩余时段约束。未连接 Outlook 且未设手动上限时，仅保留原场景排期，不猜测空闲时间。

估时优先级：描述 `content`，其次描述 `desc`，再标题或标签中的时长标注、任务起止区间，最后使用默认估时。标注支持 `(1m)`、`(1h)`、`(1h1m)`、`(1.5h)` 等格式，小数分钟向上取整；新增标注统一采用英文括号和小写单位，已有耗时保留。

## 6. 完成记录与日期写入

- 首次分段读取近 60 天完成记录；后续增量读取，并持续保存每个任务和重复系列的最后一次完成。
- 重复任务完成后历史 ID 可能变化；同清单、同父任务、同名且唯一的系列可以匹配，不跨同名歧义猜测。
- 普通轮换的重复周期截止优先按最近实际完成日期和重复规则计算；没有可用记录时使用保存的原日期锚点。
- 实际做过任务与在 TickTick 中勾选完成是两件事。程序只能使用读到的完成记录；读不到记录不能直接解释为用户没有做过。
- 已结束的一次性安排不能挂在小时重排、完整同步或经期归档中反复执行。2026-10-09／10 的电动车充电与取车安排已退役，旧入口返回 `410`，不再把下一轮循环任务改回历史日期，也不补建已完成的旧任务。
- 完成记录读取失败时停止本轮每日安排；Outlook 订阅读取失败时停止本轮排程并保留旧数据。
- 场景日期与普通轮换先合并，再写最终日期，避免一次同步往返改期。
- 改期保留任务时刻、时区、起止间隔、优先级、标签、提醒及重复规则与起算方式。无日期任务补全天日期。
- Checklist 仅平移有日期的未完成项，无日期项不补日期，已完成项不改动。
- 写入后回读验证；只有日期写入与验证成功后才发布本轮安排结果，不能把旧快照解释为当前结果。

## 7. 专门管理的任务

| 任务类型 | 排期依据 |
| --- | --- |
| 洗头日期跟随 | 带 `洗头` 标签的任务跟随唯一未完成「洗头」任务的日期，优先于自身场景及循环规则。来源缺失或无日期时保留，多来源时报错。 |
| 洗衣服 | 按最近完成与重复规则确定目标日，在前一天至后两天内结合场景、空闲与天气选择。目标日在出行期间时优先安排出行前一天；已经在出行前一天洗过不重复倒排，错过则保留等待补做。数据或合适日期不足时保留排期，不无限顺延。 |
| 训练 | 使用独立的滚动训练安排及经期、场景约束，普通轮换不覆盖。夜间未完成训练移到下一符合条件的原定训练日，不记为完成。 |
| 经期识别 | Outlook「日历」订阅中标题包含“月经”或“🩸”均计入，全天、定时、空闲与跨日日程一致处理；不额外排除“预计／预测／预估”，其他同义词不单独匹配。定时日程按北京时间覆盖日期，结束边界不额外多算一天。 |
| 月经提醒 | 预计开始前两天提醒，同一周期只提醒一次。完整同步先读取并保存完成历史：本清单本周期的提醒已完成时不再补建，预测日期调整也不重置；按最近一次经期记录划分周期，下一次记录出现后才安排下一轮。历史优先按提醒原定日期归属周期，缺少日期时使用北京时间完成日期。已自动补建的同日期重复待办在回读确认后移除，保留完成记录及已被用户改成其他内容的任务；跨年读取上一年记录。 |
| 香香喷雾与除螨喷雾 | 不能同一天，已完成的一种也占用当天。冲突时优先保留较久未完成的一种，另一种推到下一适用且无相反喷雾的日期。高优先级、定时及未来喷雾也检查。无可用日期时报错。 |
| 出行模板 | 一级阶段按名称相对行程开始日安排；二级及更深后代跟随母任务日期。一级阶段和 checklist 保留手动改期或清空日期。 |
| 心愿准备 | 已启用、有截止日且未关联出游的心愿，只生成「出门前七个月」阶段及后代；按截止日前七个自然月安排，后代跟随阶段。 |

这些任务不使用普通空档轮换决定日期；各自有不同的场景、周期与容量约束，不统一套用某一种任务的规则。

出门 todo 的各级子任务（包括心愿七个月准备阶段及后代）生成时不继承模板的 `不关我事` 标签；已有副本下次同步时也移除该标签。模板原树不改动，行程根任务及副本当前的其他标签保持不变，包括用户手动增删的 `routine`。

### 充电日程与同日改时

- 「电动车充电」复用每天四次完整同步，在 TickTick 场景和日期排程结束后，按当前未完成待办的日期补齐 Outlook 日程。不创建或改写待办，不恢复已退役的 2026-10-09／10 一次性安排，也不生成取车任务。
- 具体时间待办使用其开始时间；全天待办沿用 20:00–21:00，预约为 60 分钟。模板及其后代、已完成、无日期、历史日期及带「不关我事」的任务不创建日程。
- 充电以实际完成记录区分周期，同周期改日期更新原预约；先查找明确关联的预约、查重并回读验证。日程确实缺失时补建，重试不重复创建，保留历史活动与无关联的同名手动记录。
- 电动车充电和洗衣服的已有日程改到**北京时间同一天的其他时刻**时，后续同步保留新的开始时间，不拉回待办的默认时刻；充电仍为 60 分钟，洗衣仍为 50 分钟。待办日期跨日变化时继续跟随新日期；实际完成后开启下一周期。
- 洗衣天气排程也尊重明确关联、唯一的同日改时预约，保留当前日期，避免原时段冲突或已过去而间接撤销手动安排。上次实际完成以前的旧预约不能锁住下一周期。

### 洗衣每日动态维护

- Outlook 洗衣日程固定为 50 分钟，空档与冲突判断也使用完整 50 分钟；不受 TickTick 描述估时或起止区间影响，保留待办原有估时。
- 每天四次完整同步都重新读取 Outlook 日程并评估洗衣日期；天气缓存最多 3 小时。天气、出行或空档变化时更新 TickTick 和同一周期的 Outlook 日程，不因之前排过就停止评估。
- 完成基准取 TickTick 完成历史与 Outlook 手动洗衣记录中较新的时间。Outlook 仅接受标题为「洗衣服」、已经结束且未关联待办的具体时段；有多个有效洗衣待办时不猜归属。自动预约含待办链接，其时间结束不表示实际完成，不会自动开启下一周期。保存已确认的完成锚点，避免记录滚出近期日程窗口后回退旧周期。
- 检查空档时仅排除当前洗衣待办明确关联的预约，手动同名日程和其他任务仍占用时间。全天待办使用的 08:00 时段也须检查冲突。
- Outlook 同一周期始终先查回原日程再更新。旧 ID 查不到时按归属查重，确实缺失后使用新的幂等标识恢复；旧的「已删除」标记不再永久阻止创建。普通手动同名日程不被接管，改名、添加参与人、取消或归属异常时报告错误。
- 创建或改期时先查找明确关联同一待办的未来洗衣预约，优先复用；最新预约回读成功后，清理其他未来副本，包括旧周期和旧连接器留下的预约。删除前再次核对关联、日期、参与人及版本，删除后回读确认；保留历史日程、无关联的同名记录及被修改为其他用途的日程。清理失败不缓存为同步成功，下轮继续核对。
- 查重完整读取分页后才写入，兼容 Microsoft Graph 返回的斜杠及 OData 括号日历地址；逐页核对仍为同一日历，原样保留分页游标。分页失败或超出读取上限时停止，不把不完整结果当作没有预约。
- Make 同日同排期可复用成功回读结果，次日至少再次核对一次；排期变化立即核对并更新，避免永久依赖旧的成功状态。

## 8. 显隐规则

显隐统一通过系统专用的 TickTick `bon-hidden` 标签实现：隐藏时添加，到显示时间移除。`routine` 仅表示用户自己的例行任务，系统永远不添加或删除。

标签来源边界：凌晨临时隐藏的早晨恢复仅处理持久记录中的任务，原先手动添加且未被系统登记的 `bon-hidden` 不会全局清除。具体时间任务、阅读、洗头和夜间 routine 的专项显隐按规则管理匹配任务，到显示时间会移除该任务的 `bon-hidden`，不区分手动或系统添加。字面名称为 `hidden` 的标签不参与上述逻辑。

完整同步不再按晨间或午饭任务名称补回 `routine`；该标签只用于读取现有筛选条件。包括月经提醒在内的任务更新保留用户原有标签。

- 所有具体时间任务：仅处理 `isAllDay = false` 且有开始时间（缺少时使用截止时间）的未完成任务；时间到达前添加 `bon-hidden` 隐藏，到点后移除并显示。全天或未设置几点的任务不处理。
- 夜间 routine：保留原专项逻辑，按任务自身开始时间切换 `bon-hidden`，并设为高优先级；原有 `routine` 标签保持不变。
- 洗头：北京时间 `20:00` 前添加 `bon-hidden`，之后移除；凌晨再次隐藏。
- 阅读：仅匹配「阅读」或「而阅读📖是另一个🪝」，`20:00` 移除 `bon-hidden`，次日 `05:00` 加回，不匹配日语阅读等任务。
- 凌晨 `00:00`：临时为「🍌今日事」「🍌明日事」「‼️今天重要之事」三个智能清单范围内原本没有 `bon-hidden` 的任务添加该标签；「❕明日之重要事」不参与临时隐藏，其任务保持可见。阅读和洗头继续遵守自己的显隐规则。
- 早晨 `05:00`：依据持久记录恢复临时添加的 `bon-hidden`，不重新按当天清单范围筛选；用户的 `routine` 标签不受影响。
- 日常排程先补完待恢复标签，避免把临时隐藏误认为永久不参与。旧版 journal 只用于安全清理状态，不得据此移除用户的 `routine` 标签。

## 9. 执行时间与操作范围

- 项目定时任务全部在云端运行，业务调度使用 GitHub Actions；不创建 Codex 定时自动化，不依赖本机或浏览器持续打开。Vercel Cron 仅保留每月 1 日北京时间 08:10 的云端快照备份。
- 自动完整同步：北京时间每天 `05:00 / 12:00 / 17:00 / 20:00`，先拉取 Outlook，再执行相关排期；也可手动「立即同步」。
- 完整同步收到 `502` 时，仅对服务端明确标为可重试的读取／完成归档失败，间隔 30、60 秒最多重试两次；任务或日程写入失败、无响应及无法识别的错误仍报失败，避免重复创建。公开日志只记录 HTTP 状态和固定阶段名，不输出订阅地址、待办内容或原始错误；只有完整成功才进入后续邮件步骤。
- 每日邮件复用 05:00 完整同步工作流，在经期归档和排程都成功后通过服务端 SMTP 发送，按北京时间日期去重。手动工作流须显式启用 `send_email`，DoneList 重排不发信；旧 Codex 邮件自动化已删除。
- 普通任务每小时重排：`.github/workflows/ticktick-hourly-plan.yml` 在每小时第 7 分钟调用仅接受定时密钥的 `hourly-replan` 入口，读取最新 Outlook 空档和完成记录，复用 DoneList 的限定重排；无需打开网页。`00:00–05:00` 隐藏时段或凌晨临时标签尚未恢复时，仅维护 `always-today` 日期并跳过普通重排；TickTick 未连接时跳过，不覆盖已有安排。与完整同步、显隐工作流共用并发组与写锁。
- 每小时重排收到 `502` 时，仅对服务端明确标记的 Outlook、任务、模板或完成历史读取失败，间隔 30、60 秒最多重试两次；显隐写入、日期调整或验证失败、无响应及未知错误不自动重试。失败输出仅包含 HTTP 状态和固定阶段名，公开日志不输出待办内容、订阅地址或原始错误；失败时保留旧安排结果，不能冒充本轮成功。
- 每小时重排不运行 AI，不发送邮件；除维护 `always-today` 日期与按具体时间切换 `bon-hidden` 显隐标签外，不改其他显隐规则、训练、洗衣或 Outlook 日程。使用公开仓库的标准 GitHub Actions runner，定时触发免费；服务器和存储请求计入现有平台额度，不新增付费服务或升级套餐。
- GitHub Actions 的调度可能延迟，不能保证恰在整点执行。
- 具体时间任务随每小时重排一并核对显隐；重排在每小时第 `7` 分钟触发，受 GitHub Actions 调度延迟影响，实际显示可能再晚几分钟。`22:00` 处理夜间 routine 与未完成运动，`00:00` 临时隐藏，`05:00` 恢复并处理夜间 routine 与运动。
- DoneList「重排任务」通过服务端触发 `ticktick-daily-plan.yml` 的 `workflow_dispatch`，异步拉取 Outlook 并运行完整排期（含今天重要之事与普通今日事）；原有 `schedule` 定时触发继续保留。
