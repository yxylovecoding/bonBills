# monthlyBills

个人财务管理 Web 应用（盘账助手）— 由 `PLAN.md` 驱动开发。

## 当前状态：MVP 测试版

本阶段只做视觉骨架，用于评审页面布局和风格。数据全部来自 `src/data/mockData.ts`（从 `PLAN.md` §初始数据 摘取），不落盘、不做真实计算。

## 本地运行

```bash
npm install
npm run dev       # 开发模式 (http://localhost:5173)
npm run build     # 生产构建
```

## 安装为应用

BonBills 和 BonLife 均提供应用名称、独立图标和 Web App Manifest，可通过 Chrome 的「安装」入口以独立窗口打开。BonBills 从 `/` 启动；BonLife 子域名从 `/` 启动，主站 `/life` 安装后仍从 `/life` 启动。清单在 `src/main.tsx` 根据当前域名和路径选择，图标与清单位于 `public/`。此配置不提供离线缓存。

## BonLife 状态日历

`life.bonbills.cn` 使用同一 Vercel 项目提供独立的 BonLife 首页、图标和皮肤／情绪日历；主站的 `/life` 也可访问。子域名需要绑定到该 Vercel 项目，并在 DNS 中添加 Vercel 指定的 CNAME。沿用已有账号密码，子域名登录状态单独保存，不加载账本及其同步任务。

点击日期格编辑皮肤、情绪、体围或训练。皮肤分别记录早间、晚间用药和护肤品；体围记录胸、腰、臀、上臂、大腿、小腿围，单位 cm，支持小数和单项留空。年月选择及「往年同月」可查看、补记往年。记录按年存入独立的 `bonlife:entries:v1:*` Redis hash，每次只更新一个类型的一天，使用版本检查避免覆盖其他页面的修改。清空后保存即清除对应内容；版本标记保留，防止旧页面恢复已清空的内容。编辑中的完整草稿按账号暂存在浏览器，刷新后可继续；成功保存或明确放弃后移除。已有纯文字记录保持兼容。

「经期设置」保存最近月经开始日、周期、经期天数和每周训练日，沿用 Outlook 中已同步的经期；更新开始日时保留先前开始日期。训练安排采用用户参考图的四段模板：28 天周期的第 1–7 天为月经期（卵泡早期）、8–13 天为排卵期（卵泡中后期）、14–19 天为黄体早期、20–28 天为黄体中晚期。其他周期按相同比例伸缩；设置的较长经期及实际记录的经期优先。图示阶段是训练分组，不能用于判断实际激素水平、排卵或避孕；日期推算标为「预计」。训练页提供各阶段运动、饮食建议以及每日计划，经期前 3 天默认安排轻量活动，之后渐进恢复，黄体早期侧重力量，中晚期适当减量。可以选择轻量、休息或自行编辑并标记完成。已保存计划不随设置变化而覆盖；未保存日期随当前设置更新。没有经期日期时不推算。

运动建议是可调整的安排，不假设所有人的运动能力随周期固定变化。参考图的阶段与饮食方向经过改写：保留富铁食物、足量蛋白质、按训练量补充碳水、鱼类坚果与全谷物；不把「燃脂黄金期」「冲大重量」或「特定阶段运动会导致黄体破裂」写成普遍结论。图中所引 [McNulty 等的系统综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC7497427/) 指出效应很小、研究差异较大，应采用个体化安排。其他内容参考 [美国卫生与公众服务部女性健康办公室](https://womenshealth.gov/getting-active/physical-activity-menstrual-cycle) 和 [ACOG 经前综合征建议](https://www.acog.org/womens-health/faqs/Premenstrual-Syndrome)，不提供用药或补充剂处方。

「DoneList」复用 BonBills 已连接的 TickTick，按上海时区的实际完成日期汇总所有清单及收集箱中的任务。打开页面自动同步所选月份，可切换往月、往年补拉可用历史；页面可见时每五分钟刷新。每日现有后台任务也保存当前月份完成记录，月初补存上月末。记录存入独立的 `bonlife:done:v1:YYYY-MM` hash，以清单、任务 ID 和完成时刻区分重复任务的每次完成。重复读取不会重复计入，源端不再返回的旧记录、断开连接或同步失败均不清空已保存历史。首次补拉受 TickTick 实际提供的历史范围限制；仅归档任务，不修改 TickTick 完成状态或排期。密集结果分段读取，读取失败不标记同步成功。

在 BonLife 右上角 Outlook 入口填写 Outlook「日历」的 ICS 订阅链接。此连接与 BonBills 的「玩／课」连接独立，链接加密保存在服务端；未连接时仍可写日历。同步仅读取标题包含「月经」或「🩸」的全天日程，按事件的完整日期范围在两份状态日历显示经期，结束日期遵循 ICS 的不包含规则，支持重复、排除、改期和取消。进入某一年时自动同步该年，也可点击「同步经期」。

经期快照按年保留。仍在订阅中的事件以最新内容为准，包括更名、改期和取消；已从订阅范围消失的历史日程保留过去部分，未来部分不沿用。同步失败时保留上次完整快照，断开连接也保留历史标记。首次导入只能取得 Outlook 当前发布范围内的历史事件；尚未被订阅提供过的往年经期无法凭空补齐。

本地 `/life` 复用与生产一致的 `/api/bonlife`；需要现有 `SYNC_SECRET` 和 Vercel KV 环境变量。生产将此地址重写到 `/api/outlook-calendar?app=bonlife`，分派到独立处理器，以沿用现有部署函数数量；本地开发直接分派到同一处理器。BonLife 的经期与文字不进入财务账本的上传、合并或自动入账。

本地登录需要在 `.env.local` 配置 `SYNC_SECRET`、`KV_REST_API_URL`、`KV_REST_API_TOKEN`，建议连接开发用 KV。Vite 会转发登录及账单相关接口到同一份服务端实现。

## 登录

首次使用账号密码登录前，点击“注册账号”，输入现有 Key、自选账号和密码（至少 6 位）。服务端验证 Key 后，将账号绑定到这个 Key 对应的现有账本。一个 Key 只能绑定一个账号，重复或并发注册不能覆盖已有账号。注册后自动登录，之后只需账号密码即可进入。

不再使用固定的 `bon` 账号或把 Key 当默认密码，旧的 `LOGIN_USERNAME` / `LOGIN_PASSWORD` 环境变量不再生效。

登录页提供账号密码登录和注册入口，旧的 `?key=原同步密钥` 链接和旧标签页仍可登录。两种方式共用原有云端数据，不创建新账本；未登录或登录失败不会清空本地账单。`SYNC_SECRET` 仍用于 Key 登录、脚本鉴权及 TickTick 加密，不要为修改登录密码而更换它。

浏览器登录状态保存 30 天，退出后服务端会话立即失效。账号绑定使用 Key 的 HMAC 指纹作为索引，密码以随机盐和 scrypt 哈希保存；原始密码和 Key 不写入账号记录、前端配置或浏览器持久存储。登录接口使用原有 Vercel KV 保存绑定、会话和限制重试次数。此次升级后的旧会话需要重新登录，Key 登录一直保留。

再次打开时，服务端验证登录后会先显示该账号上次完整同步的本地账单，再后台获取最新数据。首次使用、缓存缺失或损坏时仍等待完整同步；升级后的首次成功同步会建立缓存标记。同步失败时保留已显示的数据，并可在右上角重试。

登录和账单请求每次最多等待 30 秒；恢复登录状态和读取账单遇到超时或网络中断时自动重试一次，登录、注册和保存请求不自动重复提交。持续失败时显示中文状态并保留重试入口。旧 Key 链接只在登录成功或确认 Key 无效后清除，网络失败时可继续重试。

后台同步会保留等待期间的本地编辑，未修改的字段采用云端值；同一字段两边都有变化时保留本地编辑。尚未上传的修改保存在本地，刷新后继续尝试合并和保存。输入框编辑及导入预览结束前暂缓应用云端数据，自动入账与日历补填等操作等启动同步成功后运行。缓存仅用于浏览器显示，登录和账单接口继续禁用公共缓存。

## 163 邮箱账单导入

记录页的“邮箱导入”会通过服务端 IMAP 拉取最近匹配 `账单_数字.xls/xlsx` 的附件，然后复用前端账单导入规则；全量账单在生成预览时就会导入，预览仅决定是否更新账户和理财操作。如果最新附件是图片，则自动走本地 OCR 并按内容判断资产页或理财页。

部署环境需要配置：

```bash
SYNC_SECRET=现有同步密钥（用于 Key 登录和注册验证）
CRON_SECRET=Vercel 定时任务鉴权密钥（每日日历与待办同步、每月云端快照）
BILL_MAIL_USER=你的163邮箱
BILL_MAIL_PASS=163客户端授权码
```

可选配置：

```bash
BILL_MAIL_HOST=imap.163.com
BILL_MAIL_PORT=993
BILL_MAIL_LOOKBACK_DAYS=90
BILL_MAIL_SCAN_LIMIT=80
BILL_ATTACHMENT_PATTERN=^账单_\d{10}\.xlsx?$
BILL_IMAGE_ATTACHMENT_PATTERN=\.(png|jpe?g|webp|gif|bmp|tiff?)$
```

## 待确认基金买入

进入 Web 后会自动查询当前月份待确认基金的历史单位净值。对应净值公布后，自动把预估份额和买入成本计入持仓，并隐藏原待确认行，页面只展示更新后的持仓。按北京时间 15 点截单，周末及净值记录中暂停申购的日期顺延。净值未公布时继续等待，同一基金同月份复用查询，缓存 15 分钟；查询失败一分钟后重试，切回页面也会检查更新。

手续费明确时先扣费计算，未知时暂按费前份额入账；缺少操作时间、金额、明确基金报价源或订单身份有歧义时继续等待。下次导入正式账单时，后台匹配原自动入账记录并校正份额、净值、手续费和成本，重算后续买卖的影响；重复导入和旧待确认记录不会再次累加，校对标记仅内部保存。跨月迟发的净值入当前月份，保留此前月末快照；银行实际确认日期另存于交易记录。导入预览期间暂停自动入账。

## BonCV FIRE 联动

首页 FIRE 可以从 BonCV 单向同步出生日期、最高学历和毕业日期。BonCV 连接密钥只保存在服务端，浏览器通过受登录会话保护的代理读取最小字段。

```bash
BONCV_API_BASE_URL=https://你的-boncv-域名
BONCV_API_KEY=从 BonCV“连接”页面创建的 fire:read 密钥
```

连接失败时会保留上次成功快照；也可在 FIRE 详情中切换为手工维护。

FIRE 年薪从预计毕业就业时间起算，每满一个就业年度上涨 10%；在读期间沿用记录中的月均收入和在读支出，不生成工资或公积金。默认情景为杭州无房、非杭州户籍、当前公积金余额 0。

FIRE 后的居住场景可单击切换“寄 / 居”，“旅”为独立开关。独居使用“校”的日常支出样本，并加上“未来固定支出”中已启用的房租；在家不计这笔房租，其他固定支出照常计入。旅行按历史天数占比加权日常支出（包含记录中的旅行住宿），长期房租仍按全年计入一次，出游期间两种住宿开销同时承担。旧的“校 / 校＋旅行”配置分别沿用为“独居 / 独居＋旅行”。此开关仅改变退休后的支出，毕业前和工作期的支出保持原有分段。

公积金按个人与单位同额缴存。无房且设置租房支出时，青年或新市民按双边缴存额计算租赁提取，普通杭州市区租赁限额为 2000 元/月；同一期间在适用情形中取较高额度，不叠加，实际提取不超过账户余额。新就业连续缴存满 3 个月后计入首次提取。未提取余额单独累计，不预估利息；按 FIRE 时离职、不再就业缴存且封存满半年后的余额提取测算，折回目标时点，并保留半年生活费及大额愿望所需流动资金。当前公积金余额不能同时计入理财总额。户籍、落户日期、余额和提取开关可在现有 FIRE 详情中维护。

政策依据：[租赁提取政策](https://zfgb.hangzhou.gov.cn/11/105220253/t117220253054/518769.shtml)、[青年与新市民实施细则](https://gjj.hangzhou.gov.cn/art/2023/12/29/art_1229468386_1839436.html)、[离职提取新政](https://zfgb.hangzhou.gov.cn/11/105220253/t119220253054/519177.shtml)。

## Outlook 月历同步

「记录 → 月 → 设置」中的 Outlook 入口支持订阅「玩」「课」日历。在 Outlook 网页端的「设置 → 日历 → 共享日历 → 发布日历」中，分别生成可查看标题的 ICS 链接，在此处填写后预览本月，再点击「连接并同步」。订阅链接让持有者可以读取已发布范围的日历，请使用与自己期望一致的共享范围；应用将链接加密存于服务端，不写入浏览器持久存储、代码仓库或普通账本备份。Codex 的 Outlook 授权与网页连接独立。

全天「玩」映射为出游，其中标题「🏠」映射为寄，「新卡池」「新卡池&新月卡」忽略；全天「课」中标题恰为「实习」的日程映射为班，其他全天日程也映射为出行（包括出差）。非全天日程不参与场景标记，仅用于每日待办的忙闲计算；两个日历中标题恰为「寒假」「暑假」或「教师节」「中秋节」等已知节日名称的提醒均忽略，不按关键词包含关系排除「寒假旅行」或「平遥电影节」等具体出行。多日事件不包含结束日期；重复日程按发生日展开，支持 EXDATE、改期和取消单次日程。同日冲突依次优先游、寄、班。解析或任意一个日历读取失败时保留原有标记，不把不完整结果作为取消。

出游日期始终以 Outlook 为准：完整行程覆盖本地的班、学、寄及手动留空，避免周模板把连续旅行隔成数段；缩短、改期或取消时恢复此前接管日期的原有日常标记，不恢复旧出游日期。前台、后台及旧页面上传均沿用此规则。其他日常标记默认保留手动结果；首次接入时，旧版已有的非「学」标记也会保留，旧版「学」无法区分自动补填与手动设置，作为默认值处理。也可在连接时选择日常标记以 Outlook 为准。标记及来源信息沿用账本云同步，参与已有实习天数、出游和心愿计算。

生产环境每天北京时间 09:20 的后台任务先拉取 Outlook，再按最新云端日历执行 TickTick 排期，无需打开 BonBills；未连接 TickTick 时仍会拉取 Outlook。后台按上海日期读取过去 30 天至未来 700 天（结束日不含），沿用已保存的订阅、映射规则及手动优先设置，任一日历读取失败会保留原数据并停止本轮排期。此任务复用 `/api/ticktick-trips` 的 Vercel Cron 与 `CRON_SECRET`。生产环境必须配置 `CRON_SECRET` 才能通过每日任务鉴权，修改后需重新部署。TickTick 明确返回每分钟查询限流时等待 30 秒后重试，最多两次；其他写入错误不自动重放。

TickTick「立即同步」同样先拉取上述完整日期范围的 Outlook 日程，再执行待办排期并清理失效的未来行程实例，因此无需逐月打开日历才能更新寒暑假等规则。清理沿用保存的生成任务 ID，不按名称删除普通待办；订阅读取失败时保留原任务。

进入或切换月份时仍读取当前月；页面可见时每五分钟刷新，回到页面时也会在超过五分钟后更新，并可点击「同步本月」。前台和后台都保存完整读取结果，旧页面上传时会按最新结果重新合并日历，保留明确的手动修改及账单字段。数据范围及更新延迟受 Outlook 发布的订阅内容影响，并非实时推送。断开连接会删除服务端订阅链接及同步快照缓存，保留已同步日历结果。

首页日历、月历及 TickTick 行程任务标题优先使用所选账单标签，没有标签时使用 Outlook 出游日程名称，两者都没有时用日期。日程名称不写入账单标签、筛选条件或消费归类；同步改名或取消时更新对应月份的备用标题，并触发 TickTick 任务名称更新。

「本月出游」中有名称的行程会自动创建并关联心愿，包括尚未选账单标签的 Outlook 行程及已结束的行程；没有名称的日期段待命名后补建。优先复用已经关联或唯一同名的未关联心愿（匹配时忽略账单标签的日期前缀和空格），保留预算、已攒金额、名称和启用状态。新心愿默认启用、金额待填写，截止日为出发前一天；跨月行程只建一项，手动切分后按各段关联。补建在账本完整加载及日历、出游编辑后执行，写入云同步，不需要先打开「心愿」。主动删除心愿或解除关联后，该出发日不再自动补建，仍可手动重新关联；行程取消时保留已有心愿及金额。

心愿中的「x 笔账单」在当前卡片内展开或收起匹配的账单明细，按日期从近到远展示日期、备注或分类、账户及金额；包含行前付款、跨月消费和退款，一笔账单命中多个匹配标签时只显示一次。查看明细不切换页面，也不提供手工录入入口。

已花总额和行程结束后的实际花销保留全部匹配支出，同时分别显示消费、生活及待分类金额。`消费` 标签计入心愿内欠款、已还和待攒金额；`周期生活`、`波动生活`（兼容 `生活`）只展示实际支出，不增加心愿攒款。未结束时从目标中扣除预估与实际生活费的较高者，不重复扣除；行程结束后只按实际消费计算资金需求。各类退款抵扣各自支出，生活退款不抵消费欠款。缺少核心标签或同时标为生活与消费的账单显示待分类，不直接当作消费；手填总欠款仍保留原值。首页、月度及实习阶段规划共用这一计算。

服务端沿用 `SYNC_SECRET` 和 Vercel KV，无需微软应用密钥。ICS 解析库只在服务端使用。部署后需首次填写订阅链接才会开始同步。

## TickTick 出游与场景待办

日历中的进行中及未来出游可以自动同步到 TickTick。首次使用时，在「记录 → 月 → 设置」中粘贴 TickTick 网页端“设置 → 账户 → API Token”生成的个人令牌。同步会在所有清单及收集箱中按名称查找 `出门todo模版`（兼容 `出门todo模板`）任务树作为动态模板，模板本身无需填写日期，也不要求存在 `出门当天`。一级子任务按名称（如 `出门前七个月`、`出门前两周`、`出门前3天`、`出门当天`）相对行程开始日排期，月和年按自然月计算并钳制月末，二级及更深层子任务始终跟随母任务的实际日期（包括母任务手动改期或清空日期）；生成的行程父任务统一使用“出行名称 · 出门todo”命名，只有原始模板保留“模版／模板”后缀；阶段及子任务继续使用“出行名称 · 原任务名”命名。已有行程父任务会在下次同步时原地更名，保留任务 ID、完成状态及手动日期。

出游候选标签仅会被当前仍存在的其他行程占用；已删除或重新切分行程留下的历史关联不会隐藏候选项。

已启用、设有截止日且未关联出游的心愿，以心愿截止日作为预计出发日，只同步 `出门todo模版` 中的 `出门前七个月`（兼容 `出门前7个月`）及其后代任务。阶段根任务定在截止日前七个自然月，月底不足对应日时取当月末；该阶段的所有后代任务日期与母任务一致，模板任务原有日期不参与任务排期。旧实例同步时按新规则更新自动日期，保留一级母任务的手动改期或清空日期。任务名称包含心愿名，按心愿 ID 更新改名和改期，保留完成状态；关联出游、停用或删除心愿后清理尚未到截止日的独立副本，日历完整出游任务不受影响。无截止日的心愿不生成，缺少唯一七个月模板时会报错。

出游的一级阶段任务、心愿准备的阶段根任务及 checklist 项保留手动改期或清空日期。二级及更深层模板子任务始终跟随母任务，单独修改子任务日期会在下次同步时恢复为母任务日期；一级母任务的手动日期不影响其他一级阶段。未手动调整的一级阶段按名称跟随行程或心愿截止日。模板原树、已生成的出游和心愿准备任务使用上述行程规则，不参与普通待办的场景标签排期。

API Token 使用 `SYNC_SECRET` 派生密钥加密后保存在服务端；修改行程或模板后会自动更新对应任务树，取消尚未结束的行程时会同步删除。

住宿分类使用「寄／居／旅」，日历保留「班／学／寄／游」四种标记：父母家为「寄」，「班／学」对应日常住所「居」，「游」对应旅行住宿「旅」。内部日历类型与历史数据保持兼容，班、学仍分别参与原有财务计算。

TickTick 中所有清单及收集箱内的未完成待办，按自身的「寄／居／旅」标签自动排期，兼容旧标签「寓→居」。「游」是普通分类标签，不触发旅行排期；需要旅行自动排期的待办使用「旅」。不再依赖 `在家routine／在校routine` 父任务或同名清单，不继承父任务标签；没有符合条件的待办时正常返回零项更新。

日期从上海日期的今天起查找，包含今天：「寄」取最近的寄日，没有时取今天或未来最近的春节；「居」取最近的班／学日；「旅」取最近出游开始日，正在出游则取今天。居／旅找不到日程时保留原日期。多标签比较所有有效候选日期并取最近的一天，每条待办仅更新一次。

带「居／寓」或「旅」的长周期重复任务（每隔多天、每周、每月、每年，以及限定部分日期的非每日规则），在当前场景匹配任一自身标签且已有日期时，保留滴答生成的下一次日期，逾期日期和 checklist 日期也不重排。离开所有适用场景后，统一移到日历中最近适用场景的首日，即使原定日期更晚；进入场景后由滴答继续按原重复规则循环。今天没有明确场景、找不到未来适用日或无法识别重复规则时保留原日期，不反推已被旧逻辑覆盖的历史日期。仅带「寄」的任务、普通「游」标签及每日任务沿用原规则。

需要改期时，已有日期的任务平移日期并保留时刻、时区及起止间隔；无日期任务补上目标日的全天起止日期。Checklist 仅调整已有日期的未完成项，无日期项不补期，已完成项保持原状。每日重复任务今天已完成时，从明天起重新比较全部标签候选日；连续出游中的明天也可作为旅日。长周期任务当天完成后生成的下一次日期，在适用场景内也保持不变。每次写入后回读验证，保留原重复规则及其他字段。

带「洗头」标签的未完成待办，统一跟随标题恰为「洗头」的唯一未完成待办的日期（有截止日期取截止日期，否则取开始日期，按来源任务时区判断）。日期跟随优先于寄／居／旅及自身循环排期；先完成出游、心愿和来源任务的正常排期，再同步所有清单及收集箱中的跟随项，包括本轮新生成的待办。保留各自时刻、时区、起止间隔和重复规则，Checklist 沿用上述改期规则，已完成记录不改动。来源完成后，下次同步跟随滴答生成的新待办日期；来源不存在或无有效日期时保留跟随项原日期，存在多个同名未完成来源时明确报错，不猜选来源。标题为「洗头」的任务本身不自我跟随。

每日动态安排复用每天北京时间 09:20 的后台同步及「立即同步」。沿用 bon 的智能清单范围：今日事为今天的中／低／无优先级任务，明日事为无日期、逾期及未来 30 天任务，均排除 `routine／不关我事` 标签。寄／居／旅限制先确定可执行日期，再在当天可做的任务中根据周期压力、最后实际完成时间挑选；未选中项移到明天或下一个适用场景日。高优先级任务保留原有排期并计入重要事项负担。固定时刻、无法解析的循环、出行及心愿模板树、洗头日期跟随不参与普通轮换；普通子任务使用自身标签独立参与。

每日用时默认跟随 Outlook 空档自动计算，不再使用固定 30 分钟额度或按重要事项数量打折。后台复用「玩／课」订阅的同一次读取，另展开过去 14 天至未来 31 天的具体时刻日程，保留时区、跨日、重复、排除、改期与取消；标为空闲的日程不占时间。全天标记继续用于寄／居／旅。任一订阅读取失败即停止本次排期，未连接 Outlook 且未设置手动上限时只保留原场景排期，不猜测空闲时间。

可用时段默认上海时间 09:00–22:00，排除 12:00–13:00、18:00–19:00，全天实习／出游预留 09:00–18:00；这些是可调整的作息假设，不是 Outlook 提供的精确时刻。扣除具体日程及重要事项后保留一半空档休息、通勤及应对临时安排。也可选择仅晚间 19:00–22:00，或在已完整记录睡眠、吃饭等安排时选择「跟随日历」。沿用 TickTick 设置中的单行控件，可另设 10–240 分钟的手动每日上限，留空即自动；明确保存过的旧上限会保留。

Outlook 与 TickTick 的具体时段取占用区间并集；同名且唯一对应的事项采用 Outlook 的预约时段，不重复扣除，重名歧义不猜配。固定任务及尚未安排具体时段的重要事项先预留时间。已完成的普通任务仍计入当日用量，已被日历占用覆盖的完成事项不再扣一次；当天已过去的时间不能重新利用，同日重复同步不会无限补任务。普通任务须能放入连续空档，多个碎片不能拼作一个长任务。用时优先识别标题／标签中的分钟数或已设时间区间，无明确时长时仍采用估计值。按周期剩余适用场景内的实际可用分钟分配今天应做的量，未来繁忙时今天可多分担；原周期截止日不随延期后移。容量不足时显示周期紧张及暂无空档数量，不承诺全部按期完成。未来的一次性安排不提前拉回。

完成历史首次分段读取近 60 天，后续增量读取并持续保留每个任务及重复系列最后一次完成；同清单、同父任务、同名且唯一的重复系列可匹配不同历史 ID。同名歧义不猜配；无可用完成记录时按创建时间排列。读取失败停止本轮每日安排；只有日期写入及回读成功后才发布本次安排状态。每日排期和场景排期先合并再写入，保留循环起算方式与规则，避免重复同步往返改期。

每次连接及同步都在所有清单和收集箱中只按任务名称查找模板，不限定清单名称、标签、父任务或完成状态，也不使用旧任务 ID 判断模板是否存在。优先查找 `出门todo模版／出门todo模板`，兼容旧名称 `出行todo模板／出行todo模版／出门todo／出行todo`；匹配到多个同级名称时明确报错，带行程前缀的生成副本不会被选中。模板移动或重建后，能按名称及父子关系唯一对应的已有出行、心愿任务会重新关联，保留任务 ID、完成状态、手动日期及原清单；新行程在当前模板所在清单生成。同一连接重新连接模板时不清空已有实例。

## 图片 OCR 导入

拖入图片或从邮箱获取图片附件时，会在浏览器本地通过 Tesseract OCR 识别，并按内容自动判断资产页或理财页。对账页的图片导入草稿会同步展示原图，便于和识别结果对照。账户截图按“生活=建设银行+微信、信用卡应还优先用生活正数合计减生活净额、收入=收入栏、理财现金中国银行=境内/嘉信=境外”映射，理财截图金额按 now/当前市值写入。首次使用会下载 OCR worker 与中文语言包，之后由浏览器缓存。

## Schwab 同步

Schwab 读作 `/ʃwɑːb/`，近似“施瓦布/什瓦布”。首次使用前，需要在 [Schwab Developer Portal](https://developer.schwab.com/) 创建并获批 Trader API 应用，拿到 app key、app secret，并把 callback URL 配成和本地一致，例如 `https://127.0.0.1:8182/`。

本地新建 `.env.schwab.local`，填入：

```bash
SCHWAB_CLIENT_ID=你的 app key
SCHWAB_CLIENT_SECRET=你的 app secret
SCHWAB_REDIRECT_URI=https://127.0.0.1:8182/
```

首次授权：

```bash
npm run schwab:login
```

脚本会输出授权链接。登录 Schwab 并允许访问后，把浏览器最终跳转到的完整 URL 粘回终端。token 会写到 `.schwab-token.json`，该文件已被 git 忽略。

同步账户、余额、持仓和最近交易：

```bash
npm run schwab:sync -- --days=60
```

默认输出到 `src/data/schwabSnapshot.local.json`，该文件同样不会入库。Schwab 交易查询通常限制最近 60 天，可以用 `--from=YYYY-MM-DD --to=YYYY-MM-DD` 或 `--output=PATH` 调整。
只同步余额和持仓时可加 `--no-transactions`。
