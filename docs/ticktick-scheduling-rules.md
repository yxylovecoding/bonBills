# TickTick 排任务规则

更新日期：2026-11-04。默认日期与调度时间采用北京时间（`Asia/Shanghai`）；任务自身的日期按其时区解析。

本文汇总 BonBills 当前实现、已保存的智能清单条件及 bon 在本次核查中明确的规则边界。智能清单条件来自项目在 2026-10-05 保存的记录；后续修改 TickTick 清单条件时，需要同步维护文档与相关筛选代码。具体优先级可在 DoneList 中保存调整。

## 2026-11：可配置规则、地点显隐与前序

下文的固定优先关系描述默认配置；保存用户排序后，以 DoneList「规则优先级」中的本轮配置为准。规则目录与条件说明统一定义在 `src/utils/schedulingRules.ts`，服务端所有重排入口读取同一份账号配置。

- DoneList 在「重排任务」附近展示 38 条具体规则。Outlook 出游、手动标记、回家、实习，地点／凌晨／阅读／洗头／夜间／定时显隐，场景、固定今日、游泳、训练轮换、夜间训练顺延，洗衣手动时段／出行前／天气择日，喷雾、洗头跟随、重要事项预留、最短周期、完成时间、紧迫度、普通轮换、长周期保留、最近场景日，以及模板、心愿、月经提醒以及眼药水、模板内容、搬家阶段、充电次日接车和四种 Outlook 预约均可单独排序。
- 由上到下为优先级。前序支持多选，必须先执行且优先级更高；采用保留拖动顺序的稳定拓扑排序。绑定后自动排列，拖动和键盘不能跨过祖先／后继；前后端拒绝自依赖、未知规则及环，并返回循环链。
- 规则支持自定义分组、组名、折叠、跨组归属和组内排序。组序也是执行优先级：前组的全部规则先执行，再执行下一组。组间和组内均支持指针拖动、触屏拖动和上下方向键；跨组前序先约束组序，再排序组内规则。绑定后自动调整；若规则本身无环但两组之间出现来回依赖，仍拒绝保存并显示分组循环链，不能拆散整组执行来绕过绑定。
- 规则显示名称可编辑，稳定标识和业务条件不随名称改变；前序与冲突结果采用相应配置版本的名称。删除从当前列表移除并停止后续执行，可在「已删除」中恢复到指定分组；删除不会清理此前生成的待办、日程或完成记录。其他有效规则仍绑定它时，前后端都要求先解除前序。删除状态持久保存，目录更新或跨日不会自动恢复；未命中的规则与已删除规则分别记录状态。
- 每条规则通过「→」菜单移到其他分组，包含空组。前序选择按当前分组与组内顺序展示，排除自身和已删除规则；跨组依赖仍执行原有校验。
- 规则可添加、复用和移除自定义标签，随账号规则配置保存；列表和前序选项均显示标签。每条最多 20 个标签，每个 1–30 字，去除首尾空格并去重。标签仅用于规则整理，不改变待办标签、匹配条件或执行顺序；移动、删除后恢复均保留标签。输入后直接保存也会保存尚未点击「＋」的标签。
- 旧账号首次分组按原顺序切成连续组段，保留全部已有优先级和前序。新规则加入邻近组；新增空组可保留或删除，非空组需先移出规则。规则名称最长 40 字，组名最长 30 字，组名不可重复。
- 先生成候选与约束，再按字段合并最终结果。高优先级结果胜出，包括明确保留原日期的约束；较低规则只能补充兼容结果。排期备注与日期一同裁决，防止备注描述落败的日期。原有标签、提醒、重复规则、时区、优先级和完成状态受保护。
- 每轮固定配置版本；候选阶段不写 TickTick。最终写前检查用户并发编辑和完成状态，写后回读；同一任务合并后写一次。新建树逐个确认真实 ID 后保存进度，未创建的临时 ID 不写入实例记录。训练展示快照在任务确认后刷新。
- 写前与写后均按实际时刻比较日期，兼容列表和详情接口返回不同的 UTC／时区表示。真实并发变化与写后不一致分别报告失败阶段及字段名，不展示私密字段内容，也不放宽完成状态保护。
- 前序计算或写入失败，依赖链跳过，独立分支继续；落败规则不能替代失败的高优先级结果。无匹配任务是正常完成。读取数据、完成记录保护、写锁和写后校验属于保障，不是可拖动节点。Outlook 预约只使用已确认日期；日期尚未确认则跳过，并提示把相关日期规则设为前序。
- 完整同步、小时重排和各显隐入口共用配置，同时保留各自范围。小时入口不运行训练、洗衣、模板和 Outlook 写入；独立显隐统一裁决所有显隐条件，不扩大到日期排程，零点／晨间原有固定今日维护和夜间／晨间训练顺延仍保留。单独游泳维护也遵守配置及依赖。范围外前序无本轮结果时跳过依赖，不能使用旧结果绕过绑定。
- 配置接口为 `GET/PATCH /api/ticktick-trips?action=rules`，账号隔离键 `ticktick:rules:v1` 保存版本、分组、名称、标签、删除状态、顺序和前序；过期版本返回 409。没有配置时使用默认值并继承既有 Outlook 冲突设置；新增规则补入默认位置，保留已有顺序和绑定。最近执行记录位于 `ticktick:rules:last-run:v1`，包含本轮分组和名称快照、实际顺序、版本、命中、冲突胜者及失败／跳过原因；排期详情包含同轮记录。
- 保存成功只投递一次云端完整重排。队列投递失败返回「已保存，重排未触发」，重试只重新投递，不增加配置版本。云端依据 `rulesComplete` 判断本轮结果，失败不会当作成功发邮件，也不自动重放不确定写入。

### 城市标签与日历

直接城市名来自学校、家、实习段、手动地点、穿搭地点和行程目的地，与日历共用 `readCalendarLocations`。地点明确且多个城市标签满足任一时移除 `hidden`；不匹配或当天地点不明确时添加。未带已知城市标签的任务不受地点规则影响。来源读取失败保留原显隐，并记录失败；不会将未能读取当作不匹配。多目的地但没有明确每日地点时不猜测位置。

地点规则默认位于显隐规则首位，用户可调整与阅读、洗头、凌晨、夜间及具体时刻规则的相对优先级。地点只控制 `hidden`，不改日期；`routine` 永远由用户管理。跨日重新判断，删除地点标签时只释放系统先前持有的隐藏状态。

异地实习休息日使用原学校蓝色及「休息」语义，工作日保持绿色；财务、工资与 TickTick「居」口径不变。月历每月第一段和后续换城首日显示城市，同城工休切换不重复；天气预报失败不抹掉地点。日格不再显示班／校字样，调休保留在提示与无障碍说明。默认明细，单击／起止合并切换；选日标签进入单击，明细／换标签／换月清除未完成范围。

### DoneList 的 Outlook 状态

展示所有订阅名称、独立经期订阅、Outlook 写入目标、连接状态、最近成功同步及错误，并复用已有连接管理入口。刷新页面、回到页面或轮询会重新读取连接管理后的状态。接口仅返回展示字段，不返回订阅 URL、密钥或令牌；此次不新增日程列表。规则编辑内容独立滚动，桌面和移动端的取消／保存并重排始终可见，支持指针拖动与上下方向键。

状态区明确标记「上次成功同步」，不会将其当作失败发生时间。写入错误按安全白名单显示实际原因，区分授权失效、权限不足、免费额度保护和暂时失败；只有授权失效才提示重新连接。Make 沿用最近 32 天最多 200 次中转请求的保护，不因重连或读取状态重置额度。额度暂停时只读既有调用账本并显示「下次额度释放」，额度释放后等待原有同步入口自动重试；暂停期间不会继续向 Make 发出请求。经期订阅独立重试，成功后清除其错误，不受写入额度影响；重新连接后不显示上一连接的成功时间。

## 1. 核心边界：空档补入只适用于普通任务

**“只要今天还有空档，就能把下一次任务提前拉到今天”仅适用于普通「今日事」，不能用于提前安排高优先级的「今天重要之事」。**

- 普通任务的优先级为无、低、中，对应 TickTick 数值 `0 / 1 / 3`。
- 重要任务的优先级为高，对应数值 `5`。高优先级表示重要程度，不意味着缩短重复周期。
- 例如「电动车充电」是高优先级任务，不参加普通任务的空档补入、挑选和延期。
- 高优先级任务仍可能因专门的场景、日期跟随、训练、洗衣或喷雾规则改期；必须按对应规则解释，不能归因于“今天有空档”。
- 普通轮换以“最久没做的优先”为首要规则，允许留空；不能在更久未做的可选任务仍因空档不足而等候时，用昨天刚完成的短任务填空。

## 2. 四个智能清单的范围

以下均为未完成任务，日期范围的末日包含在内。

| 智能清单 | 优先级 | 日期条件 | 排除标签 |
| --- | --- | --- | --- |
| 🍌今日事 | `0 / 1 / 3` | 今天 | `routine`、`hidden`、`不关我事` |
| 🍌明日事 | `0 / 1 / 3` | 无日期、逾期或未来 1–30 天 | `routine`、`hidden`、`不关我事` |
| ‼️今天重要之事 | `5` | 逾期或今天 | `routine`、`hidden` |
| ❕明日之重要事 | `5` | 无日期或未来 1–21 天 | `routine`、`hidden`、`不关我事`、`当天` |

「今天重要之事」有意没有排除 `不关我事`，不要把另三个清单的条件套用过来。`当天` 会排除未来重要事项的展示，但不会排除到期当天的重要事项；任务出现不必然意味着程序刚把它提前。

普通轮换代码在范围内还会处理逾期普通任务。智能清单显隐、场景改期与普通任务轮换是不同操作。

## 3. 场景标签先决定可执行日期

### `always-today` 固定今日截止日期

- 自身带 `always-today` 标签且当天没有完成过的未完成任务，截止日期在适用场景内随北京时间更新为当天，不匹配自身寄／居／旅标签时改到最近适用日；逾期、未来、无日期和仅有开始日期的任务均覆盖。移除标签后停止固定，已完成记录不修改，不向子任务隐式继承标签。
- 先读取北京时间当天的实际完成记录：当天完成过的任务或唯一重复系列保留下一次日期，当天不再拉回今天，次日恢复固定今日。优先匹配同清单的准确任务 ID；重复任务 ID 改变时仅匹配同清单、同父任务、同名且唯一的未完成系列，不跨重名歧义猜配。读取失败或记录无效时停止固定日期；写前发现重复任务日期刚变化时保留，留待下一轮核对。
- 先遵守自身场景标签；多个标签取最近适用日，没有可用场景日时保留原日期。适用场景内，这是显式日期规则，优先于重复周期、洗头跟随、训练、洗衣、喷雾错开及普通轮换。即使高优先级、带 `routine / hidden / 不关我事` 或当天没有空档，当天未完成过且场景适用时仍保持今天；原显隐规则继续生效。
- 保留时刻、时区、起止间隔、提醒、其他标签、优先级和重复设置；无日期任务补全天日期，缺截止日期时补上。Checklist 沿用现有未完成有日期项调整规则。
- 复用云端零点显隐同步、每天 00:01 和 05:01–23:01 的小时核对及四次完整同步；00:30–05:01 不执行任何自动任务。其他自动入口也遵守休息窗口；允许执行时仍维护未在当天完成的任务日期，暂停普通重排。云端触发或前序同步可能延迟，实际更新发生在任务执行时。
- 可见的普通固定今日任务先预留当天耗时，高优先级任务沿用重要事项预算；普通轮换不能将其延期。

- 部署检查覆盖所有 API 入口的运行时导入链，包括共用的 `src` 工具；相对导入必须带 Node ESM 输出扩展名，避免本地测试通过、线上却在加载重排模块时中断，导致固定今日等规则全部未执行。

- 读取所有清单和收集箱中的未完成任务，使用任务自身的 `寄 / 居 / 旅` 标签；普通子任务不继承父任务标签。
- `寄` 对应父母家；`居` 对应日历的班、学；`旅` 对应旅行。旧标签 `寓` 按 `居` 处理，普通分类标签 `游` 不触发旅行排期。
- Outlook 全天日程标题包含“月经”或“🩸”时不参与出行场景、行程名称或出行心愿生成，包括预计／预测／预估日程。同日真实旅行单独保留；同步时按已保存的标题与 Outlook 来源清理历史误标，恢复原场景，旧缓存重放也遵守此规则。经期记录仍按「日历」订阅独立识别。
- 从今天起查找最近的适用日，包含今天。任何场景找不到可确认的适用日时保留原日期。
- 同时带多个场景标签时，比较有效候选日并取最近的一天。

### 长周期重复任务的当前实现

对于带 `居 / 寓` 或 `旅` 的长周期任务，每隔多天、每周、每月、每年及限定部分日期的非每日规则均按长周期处理：

1. 当前场景匹配任一自身标签，且已有日期：保留 TickTick 生成的下一次日期，包括逾期日期和对应 checklist 日期。
2. 离开所有适用场景：移到日历中最近适用场景的首日，**即使原日期更晚**。
3. 今天场景不明确、找不到未来适用日或无法解析重复规则：保留原日期。
4. 进入适用场景后，由 TickTick 按原重复规则继续循环；当天完成后生成的下一次长周期日期也保留。

这层场景同步没有统一排除高优先级任务。因此，“高优先级不参加空档补入”不等于“完整同步绝不修改高优先级日期”。仅带 `寄` 的任务不适用上述 `居 / 旅` 长周期日期保护，仍沿用最近场景日规则。

每日重复任务当天已完成时，从明天开始比较场景候选日，避免当天再次安排。

## 4. 普通任务的挑选与延期

### 候选范围

- 处理普通、未完成且不带 `routine / hidden / 不关我事` 的任务。
- 已有日期不能超过未来 30 天；无日期及逾期普通任务也可参与。
- 今天必须符合任务自身的场景标签；今天不适用时，不因久未完成或剩余时间多而拉回今天。
- 固定时刻任务、无法解析的重复规则、出行与心愿模板树、洗头及洗头日期跟随项不参加普通轮换。训练和洗衣由专门逻辑管理。
- 同一个重复系列今天已经完成时，本次不再选入。

### 挑选顺序

1. 没有匹配完成记录的任务优先补齐轮换，不把创建或改期时间当作实际完成时间。
2. 有完成记录的任务按上次实际完成时间从早到晚挑选，即“最久没做的优先”。周期到期或自动改期不能让最近完成的任务插队。
3. 完成时间相同或都没有记录时，再比较紧迫程度：周期或原定截止日已到、没有下一适用场景日，或下一适用场景日晚于截止日的任务优先。
4. 最后按截止日、创建时间和任务 ID 确定稳定顺序；简报保留本轮实际挑选顺序。
5. 任务必须放入一个连续空档，并满足剩余额度与喷雾互斥规则。若更久未做的可选任务因空档不足而待安排，不用昨天刚完成的任务填空；没有后续适用场景而必须保留的今日任务仍可保留。

周期分摊值只用于说明，不限制本轮分钟数；可继续从「明日事」补入符合上述顺序与约束的普通任务，直到没有可安排候选，不要求凑满。

### 未入选任务

- 今天及逾期的普通任务未入选时，移到明天或下一个适用场景日。
- 未来或无日期任务未入选时，保留原日期，包括继续无日期。
- 当前任务没有后续适用场景日时可能保留在今天，并明确说明时间不足，需要手动协调。
- 延期不是完成，不能让原周期截止日跟着延期向后移动。

## 5. 时间预算与估时

- 自动预算依赖 Outlook 的实际空档。默认可用时段为 `09:00–11:00`、`14:00–18:00`、`20:00–22:00`。
- 所有模式均排除 `11:00–14:00` 的午饭与休息、`18:00–20:00` 的晚饭与休息。
- 可选仅晚间 `20:00–22:00`，或跟随日历并排除餐休。所有模式都不因「旅」等日期场景标记或 Outlook 全天日程扣减可用时间，也不自动预留 `09:00–18:00`；只按具体时刻的日程计算占用。任务自身的寄／居／旅适用范围及专项日期规则继续生效。
- 每轮从实际执行时刻裁剪当天时段，只使用尚未过去的时间；定时延迟也按实际执行时间计算。
- Outlook 与 TickTick 的具体占用时段取并集。同名且唯一对应的事项不重复扣时，重名歧义不猜配。
- 固定普通任务需要预留时间；已完成普通任务仍计入当日用量，防止完成后无限补入。
- 今日未完成的重要事项先占用剩余时间，再安排普通任务。未定时或已错过预约但未完成的事项按估时预留；已有尚未结束的唯一对应 Outlook 日程或 TickTick 定时区间时，只扣实际区间，不重复扣估时。重要清单按高优先级、逾期／今天及非 routine／hidden 筛选，不排除「不关我事」。
- 页面直接使用同一轮后台保存的日程占用、重要事项扣除后剩余和新增额度，不在前端另扣一次重要事项。重要事项汇总显示本步实际扣除的时间；已被日程覆盖时显示另需时间。
- 多个碎片空档不能拼成一个长任务。没有额外休息缓冲，也不使用固定 30 分钟额度或按重要事项数量打折。
- 可保存 `10–240` 分钟的手动每日上限；上限仍受当天实际剩余时段约束。未连接 Outlook 且未设手动上限时，仅保留原场景排期，不猜测空闲时间。

估时优先级：描述 `content`，其次描述 `desc`，再标题或标签中的时长标注、任务起止区间，最后使用默认估时。标注支持 `(1m)`、`(1h)`、`(1h1m)`、`(1.5h)` 等格式，小数分钟向上取整；新增标注统一采用英文括号和小写单位，已有耗时保留。

## 6. 完成记录与日期写入

- 首次分段读取近 60 天完成记录；后续增量读取，并持续保存每个任务和重复系列的最后一次完成。
- 重复任务完成后历史 ID 可能变化；同清单、同父任务、同名且唯一的系列可以匹配，不跨同名歧义猜测。
- 普通轮换的重复周期截止优先按最近实际完成日期和重复规则计算；没有可用记录时使用保存的原日期锚点。
- 实际做过任务与在 TickTick 中勾选完成是两件事。程序只能使用读到的完成记录；读不到记录不能直接解释为用户没有做过。
- 已结束的一次性安排不能挂在小时重排、完整同步或经期归档中反复执行。2026-10-09／10 的电动车充电与取车安排已退役，旧入口返回 `410`，不再把下一轮循环任务改回历史日期，也不补建已完成的旧任务。
- 完成记录读取失败时停止本轮每日安排；Outlook 订阅读取失败时停止本轮排程并保留旧数据。
- 场景日期与普通轮换先合并，再写最终日期，避免一次同步往返改期。
- 改期保留任务时刻、时区、起止间隔、优先级、标签、提醒及重复规则与起算方式。无日期任务补全天日期。
- Checklist 仅平移有日期的未完成项，无日期项不补日期，已完成项不改动。
- 写入后回读验证；只有日期写入与验证成功后才发布本轮安排结果，不能把旧快照解释为当前结果。

## 7. 专门管理的任务

| 任务类型 | 排期依据 |
| --- | --- |
| 洗头日期跟随 | 带 `洗头` 标签的任务跟随唯一未完成「洗头」任务的日期，优先于自身场景及循环规则。来源缺失或无日期时保留，多来源时报错。 |
| 洗衣服 | 按最近完成与重复规则确定目标日，在前一天至后两天内结合场景、空闲与天气选择。目标日在出行期间时优先安排出行前一天；已经在出行前一天洗过不重复倒排，错过则保留等待补做。数据或合适日期不足时保留排期，不无限顺延。 |
| 训练 | 使用独立的滚动训练安排及经期、场景约束；每个候选日先检查自身寄／居／旅标签再参加轮换，不因接管训练而绕过场景。普通轮换不覆盖。夜间未完成训练移到下一符合条件的原定训练日，不记为完成。 |
| 经期识别 | Outlook「日历」订阅中标题包含“月经”或“🩸”均计入，全天、定时、空闲与跨日日程一致处理；不额外排除“预计／预测／预估”，其他同义词不单独匹配。定时日程按北京时间覆盖日期，结束边界不额外多算一天。 |
| 月经提醒 | 预计开始前两天提醒，同一周期只提醒一次。完整同步先读取并保存完成历史：本清单本周期的提醒已完成时不再补建，预测日期调整也不重置；按最近一次经期记录划分周期，下一次记录出现后才安排下一轮。历史优先按提醒原定日期归属周期，缺少日期时使用北京时间完成日期。已自动补建的同日期重复待办在回读确认后移除，保留完成记录及已被用户改成其他内容的任务；跨年读取上一年记录。 |
| 香香喷雾与除螨喷雾 | 不能同一天，已完成的一种也占用当天。冲突时优先保留较久未完成的一种，另一种推到下一适用且无相反喷雾的日期。高优先级、定时及未来喷雾也检查。无可用日期时报错。 |
| 出行模板 | 一级阶段按名称相对行程开始日安排；二级及更深后代跟随母任务日期。一级阶段和 checklist 保留手动改期或清空日期。 |
| 心愿准备 | 已启用、有截止日且未关联出游的心愿，只生成「出门前七个月」阶段及后代；按截止日前七个自然月安排，后代跟随阶段。 |

这些任务不使用普通空档轮换决定日期；各自有不同的场景、周期与容量约束，不统一套用某一种任务的规则。

出门 todo 的各级子任务（包括心愿七个月准备阶段及后代）生成时不继承模板的 `不关我事` 标签；已有副本下次同步时也移除该标签。模板原树不改动，行程根任务及副本当前的其他标签保持不变，包括用户手动增删的 `routine`。

### 充电日程与同日改时

- 「电动车充电」复用每天四次完整同步，在 TickTick 场景和日期排程结束后，按当前未完成待办的日期补齐 Outlook 日程。不创建或改写待办，不恢复已退役的 2026-10-09／10 一次性安排，接车按充电次日北京时间 07:20–07:40 创建或更新 TickTick 待办和 Outlook 日程，保留已完成及历史记录；同周期改期更新关联待办，重复运行不新增副本。
- 具体时间待办使用其开始时间；全天待办沿用 20:00–21:00，预约为 60 分钟。模板及其后代、已完成、无日期、历史日期及带「不关我事」的任务不创建日程。
- 充电以实际完成记录区分周期，同周期改日期更新原预约；先查找明确关联的预约、查重并回读验证。对应待办变化触发同步时，日程确实缺失才补建，重试不重复创建，保留历史活动与无关联的同名手动记录。
- 电动车充电和洗衣服的已有日程改到**北京时间同一天的其他时刻**时，后续同步保留新的开始时间，不拉回待办的默认时刻；充电仍为 60 分钟，洗衣仍为 50 分钟。待办日期跨日变化时继续跟随新日期；实际完成后开启下一周期。
- 洗衣天气排程也尊重明确关联、唯一的同日改时预约，保留当前日期，避免原时段冲突或已过去而间接撤销手动安排。上次实际完成以前的旧预约不能锁住下一周期。

### 洗头日程

- 「洗头」复用洗衣、充电的 Outlook 写入连接，每天四次完整同步在场景与日期排程完成后，按最终未完成待办日期补齐日程。仅匹配标题为「洗头」的任务，不将带「洗头」标签的其他准备项创建为洗头日程。
- 按待办日期安排北京时间 22:00–22:30，固定 30 分钟，不受待办原时刻或估时影响。保留原待办及其标签、周期和显隐规则；routine、hidden 不阻止日程同步。
- 排除模板树、已完成、无日期、历史日期和「不关我事」任务。按实际完成记录区分周期，同周期改日期更新原预约；同日手动改时保留；对应待办变化触发同步时，缺失预约查重后补齐，重复同步不新增副本。保留历史活动和无关联的手动同名日程。
- 设置中统一显示「连接 Outlook」，DoneList 不再展示洗衣专属连接。同步失败写入连接状态并使云端本轮完整同步报告失败。

### 洗衣每日动态维护

- 成功评估洗衣日期后，将周期目标、实际完成基准、当日及次日天气、场景城市和安排依据写入 TickTick 备注的「洗衣安排原因」区块；同日也刷新，保留区块外原备注和估时。出行前固定日期及手动改时明确标注未按天气择日，不把缺测写成晴天。

- bon 的洗衣周期为每五天一次，以最近实际完成日加五天计算目标，在目标日前一天至后两天选日。所有周期都继续遵守出行、天气和空档规则；天气改期后保留原周期锚点，缺少候选日天气或日程时保留当前排期。
- 天气请求使用预报天数，避免北京时间跨日时手算末日超出服务允许范围；保留完整日期的预报，远期缺测不影响近期窗口。候选洗衣日及次日缺测时仍停止改期，不把缺测当作无雨。
- Outlook 洗衣日程固定为 50 分钟，空档与冲突判断也使用完整 50 分钟；不受 TickTick 描述估时或起止区间影响，保留待办原有估时。
- 每天四次完整同步都从现有 Outlook 订阅读取日程并评估洗衣日期；天气缓存最多 3 小时。天气、出行或空档变化时重新评估 TickTick 排期，最终待办排期实际变化才同步对应的 Outlook 日程；评估结果不变时不调用写入连接。
- 完成基准取 TickTick 完成历史与 Outlook 手动洗衣记录中较新的时间。Outlook 仅接受标题为「洗衣服」、已经结束且未关联待办的具体时段；有多个有效洗衣待办时不猜归属。自动预约含待办链接，其时间结束不表示实际完成，不会自动开启下一周期。保存已确认的完成锚点，避免记录滚出近期日程窗口后回退旧周期。
- 检查空档时仅排除当前洗衣待办明确关联的预约，手动同名日程和其他任务仍占用时间。全天待办使用的 08:00 时段也须检查冲突。
- Outlook 同一周期需要更新时先核对原日程及版本。旧 ID 查不到时按归属查重，确实缺失后使用新的幂等标识恢复；旧的「已删除」标记不再永久阻止创建。普通手动同名日程不被接管，改名、添加参与人、取消或归属异常时报告错误。
- 创建或改期时先查找明确关联同一待办的未来洗衣预约，优先复用；最新预约回读成功后，清理其他未来副本，包括旧周期和旧连接器留下的预约。删除前再次核对关联、日期、参与人及版本，删除后回读确认；保留历史日程、无关联的同名记录及被修改为其他用途的日程。清理失败不缓存为同步成功，下轮继续核对。
- 查重完整读取分页后才写入，兼容 Microsoft Graph 返回的斜杠及 OData 括号日历地址；逐页核对仍为同一日历，原样保留分页游标。分页失败或超出读取上限时停止，不把不完整结果当作没有预约。
- Make 和微软直连对四类日程均复用按账号、目标日历、待办、周期和有效排期保存的成功结果，不按时间失效。排期内容包括日期、时刻、时长和地点；对应待办排期或周期没有变化时为零次 Outlook 请求、零次写入，包括跨天和同一日历重新连接。只有首次同步、对应排期或周期变化、上次同步尚未确认成功时重新查重和同步；其他待办、显隐标签、优先级及不影响排期的备注变化不触发该日程。同轮同类多个待办复用完整查重列表，并及时更新本轮结果。
- 不进行每日、每周或预约当天的额外核验。用户仅在 Outlook 中修改或删除已确认的日程时保持原状，不自动覆盖或补建；直到对应待办排期或周期发生变化才处理该日程。届时发现缺失则完整查重、补建并验证，同日手动改时继续保留。上次写入响应丢失或核验失败属于未完成的同步，可继续恢复，不能记为成功而漏掉重试。
- 创建和修改仍保留写后回读；没有发生写入的已有日程复用刚读取的结果。删除旧副本之前仍重新核对保留项和副本，保护历史、参与人、完成记录及用户并发修改。读取失败不丢弃既有成功记录，发生写入前才将成功缓存失效，避免失败重试重复创建或改期。
- 每类同步在服务端连接记录的 `syncUsage` 中记录最近一轮实际 GET／POST／PATCH／DELETE 次数、缓存跳过数及失败状态；额度检查拒绝且未发送的请求不计数。历史额度账本只记录次数和时间，不能追溯过去每次请求的方法。额度仍为原有最近 32 天最多 200 次保护，不清空、不提高，也不新增付费调用。

## 8. 显隐规则

显隐统一通过系统专用的 TickTick `hidden` 标签实现：隐藏时添加，到显示时间移除。`routine` 仅表示用户自己的例行任务，系统永远不添加或删除。

标签来源边界：凌晨临时隐藏的早晨恢复仅处理持久记录中的任务，原先手动添加且未被系统登记的 `hidden` 不会全局清除。具体时间任务、阅读、洗头和夜间 routine 的专项显隐按规则管理匹配任务，到显示时间会移除该任务的 `hidden`，不区分手动或系统添加。旧名 `bon-hidden` 继续按隐藏状态读取；匹配显隐规则后，隐藏时统一写为 `hidden`，显示时移除两种名称。未命中规则或来源读取失败时不全局改标签；其他标签和任务字段保持不变。

完整同步不再按晨间或午饭任务名称补回 `routine`；该标签只用于读取现有筛选条件。包括月经提醒在内的任务更新保留用户原有标签。

- 所有具体时间任务：仅处理 `isAllDay = false` 且有开始时间（缺少时使用截止时间）的未完成任务；时间到达前添加 `hidden` 隐藏，到点后移除并显示。全天或未设置几点的任务不处理。
- 夜间 routine：保留原专项逻辑，按任务自身开始时间切换 `hidden`，并设为高优先级；原有 `routine` 标签保持不变。
- 洗头：北京时间 `20:00` 前添加 `hidden`，之后移除；凌晨再次隐藏。
- 阅读：仅匹配「阅读」或「而阅读📖是另一个🪝」，`20:00` 移除 `hidden`，次日 `07:01` 加回，由该小时队列先执行阅读显隐；晨间排程提前到 `05:01` 不改变阅读窗口，不匹配日语阅读等任务。
- 凌晨 `00:00`：临时为「🍌今日事」「🍌明日事」「‼️今天重要之事」三个智能清单范围内原本没有 `hidden` 的任务添加该标签；「❕明日之重要事」不参与临时隐藏，其任务保持可见。阅读和洗头继续遵守自己的显隐规则。
- 早晨 `05:01`：依据持久记录恢复临时添加的 `hidden`，不重新按当天清单范围筛选；用户的 `routine` 标签不受影响。
- 日常排程先补完待恢复标签，避免把临时隐藏误认为永久不参与。旧版 journal 只用于安全清理状态，不得据此移除用户的 `routine` 标签。

## 9. 执行时间与操作范围

- 项目定时任务全部在云端运行：Cloudflare Workers Cron 触发，SQLite Durable Object 持久队列按顺序调度现有 Vercel 接口，应用数据保存在 Turso。不创建 Codex 定时自动化，不依赖本机或浏览器持续打开。Vercel Cron 仅保留每月 1 日北京时间 08:10 的云端快照备份。
- 普通任务在北京时间每天 **00:01、05:01–23:01** 触发（UTC cron `1 0-16,21-23 * * *`）；**00:30–05:01 暂停全部自动任务**，接口和队列也跳过延迟到此窗口的所有自动执行；每天完整同步保留北京时间 `05:01 / 12:00 / 17:00 / 20:00`。`22:00` 处理夜间 routine 与未完成运动，`00:00` 临时隐藏，`05:01` 先恢复显隐再完整同步；`20:00` 先显示洗头与阅读。
- 完整同步先导入并持久保存经期，再拉取 Outlook 和排程。经期导入失败仍继续排程，保留旧历史；失败会记录为失败，不冒充成功。05:01 经期归档和完整排程均成功后才发送每日邮件，邮件沿用服务端上海日期去重。
- 每小时入口仍为受定时密钥保护的 `hourly-replan`，读取最新 Outlook 空档与完成记录。00:30–05:01 先直接跳过，不读取完成历史或修改待办；00:01 或 05:01 前及凌晨临时标签未恢复时，仅维护未在当天完成的 `always-today` 日期并跳过普通重排；未连接 TickTick 时跳过，不覆盖已有安排。
- 每小时重排不运行 AI、不发邮件；除 `always-today` 日期与具体时间任务的 `hidden` 显隐外，不执行训练、洗衣或 Outlook 日程专项同步。使用 Cloudflare 免费套餐，Vercel 和 Turso 请求仍计入各自已有额度。
- 队列串行执行完整同步、小时重排和显隐任务；同一计划时刻重复投递只入队一次，已有同类任务等待或运行时合并网页触发。继续使用服务端 TickTick 写锁。占用写锁时每 30 秒等待一次，最多 12 次；小时接口的 `deferred` 也按等待处理。
- 仅对服务端明确标记可重试的读取失败，在 30、60 秒后最多重试两次；完整同步还允许明确标记的完成归档重试。经期独立归档是幂等操作，最多重试两次，间隔 10 秒。持久显隐恢复最多继续 40 批；未知错误、写入失败及无响应不自动重发。
- TickTick 单次读取遇到网络错误时，在 1、2 秒后最多重试两次；任务创建、更新、删除的网络结果未知时不重发。该读取恢复不会重跑已经完成的排程步骤。
- 每次调用 Vercel 前持久记录执行中状态，响应后保存结果并唤醒下一步。单次 alarm 只调用一次接口（最长 320 秒），完整流程可分步超过 15 分钟。进程重启且响应未知时记录失败，不盲目重放。等待超过 45 分钟或跨上海日期的旧任务停止，避免旧安排或旧邮件迟到执行。
- 调度记录只保存时间、固定阶段与成功／失败类别；调度专用 API 响应只返回完成标志，不保存待办内容、健康记录、订阅地址、凭据或原始错误。查看调度状态和手动触发都需要服务端密钥。
- DoneList「重排任务」通过服务端投递 Cloudflare 队列，异步执行经期导入和完整同步，不发邮件。GitHub Actions 的自动与手动工作流均已移除，所有这些任务都不再交给 GitHub 执行。
- 05:01 合并为一次晨间流程：显隐恢复 → 经期归档 → 完整同步（含当天重排）→ 每日邮件；不另外投递小时重排。显隐恢复失败时停止后续流程，归档或排程未完成时不发邮件。
- 01 分是计划触发时间，云端投递、前序任务和外部 API 仍可能造成延迟，不承诺精确秒级完成。

### 实习居住城市与工休

- 设置中的上学城市与实习段的居住城市分别保存。实习段绑定公司规则快照和包含首尾的起止日期；城市、规则按日期解析，模板更新不回写旧实习段。
- 上学城市可按起止月份分阶段，包含首尾月份；未覆盖月份沿用默认上学城市。只解析已有场景的所在地，不因上学阶段新增任务日期或覆盖回家、出游及实习居住。洗衣候选日和 Outlook 地点同步使用该日期的城市。
- `寄 / 居 / 旅` 的任务范围不变：实习工作日与异地实习休息日都属于 `居`。本地实习休息日沿用 `校`；异地周末继续居住在实习城市。明确的回家、出游安排优先，单日城市覆盖独立于是否出勤。
- 完整同步与每小时重排使用同一实习日期解析。工资采用各公司工作日与单日出勤规则，连续 Outlook「实习」全天标记不等于周末出勤；工资计算不占用任务空档。
- 洗衣在原候选窗口内按每个候选日期的城市查询天气，缓存按坐标隔离；Outlook 地点跟随最终日期。缺少城市或天气时保留排期，50 分钟时长和同日手动改时规则继续生效。

### 出门与搬家模板内容对齐

- 每小时重排与完整同步均在 TickTick 写锁内同步 10 组二级子任务：漱、护、妆、浴、相机、衣物、随身背包、白色小袋子、黑色小袋子，以及搬家的 📦 与出门的 🧳【⚪️／🤍】。不匹配生成的行程副本；首次匹配后按任务 ID 保持关联。
- 双向共享标题正文、备注和 checklist 内容／顺序；各自 🎒🧳📦 前缀、阶段父任务、日期、标签及已有 checklist 完成状态保持不变。特殊容器一组保留各自完整标题，仅共享内部内容。
- 按同步基准识别单边修改；首次差异或双边修改按 TickTick modifiedTime 选择较新版本。首次缺少可比较时间按 bon 2026-11-01 授权以出门模板为准；后续双边修改缺少时间或时间相同则报告冲突；缺失或重复匹配停止写入。每组写入前回读检查并在写入后验证，验证成功才保存基准。
- 手动「重排任务」队列为专项显隐（包括睡眠临时标签、固定今日、夜间任务、具体时刻、阅读、洗头及训练）→ 经期导入 → 完整同步；完整同步覆盖模板内容、出行／心愿、场景与普通轮换、训练、洗衣、喷雾、月经提醒以及相关 Outlook 日程。不发送邮件，已退役的一次性任务不再执行。

- 标题含 `搬家-` 的任务树（如「搬家-京广」）也同步其已有的二级匹配项。先对齐两份模板，再由搬家模板单向更新这些实例；实例内容不会反写模板。保留各实例容器前缀、父任务、日期、标签、完成状态和已有清单项进度；未包含的类别不自动补建，无关子任务不修改。首次按上述 10 类匹配后记录任务 ID，后续改名仍可跟随；重名歧义停止该实例同步。

### 每天首次有效 replan

北京时间 05:01 起，当天首次有效 replan 先执行完整排程，维护充电、接车、洗头、洗衣的 TickTick 待办及 Outlook 日程。晨间完整同步成功已覆盖时，后续 replan 沿用普通小时范围；任一专项失败不写成功标记，下次 replan 再核对补齐。按账号、连接和上海日期隔离；00:01 继续只维护固定今日，00:30–05:01 继续暂停。此规则不代表每天都安排做这些事项，日期仍遵守各任务周期、场景和天气规则。

### 眼药水过期项去重

每小时重排（`hourly-replan`）及完整同步检查「今天重要之事」中标题恰为「眼药水」的定时重复待办，仅保留最近到期的一项，其余已过期项按原重复规则推进到下一次尚未到达的时刻。未来项、其他名称、routine／hidden、已完成及非高优先级任务不处理。通过公开更新接口推进日期，不写完成记录、不删除重复系列，保留提醒、标签和重复设置；到下一时刻前由原显隐规则隐藏。

重复眼药水由原循环日期管理，不参加 always-today、场景改期、洗头跟随或普通空档补入，因此小时重排与完整同步均不能把下一次拉回。重复执行不继续推进尚未到期项。写前核对保留项与被跳过项，写后回读验证；有限次数／结束日期、按完成时间循环和带清单子项的特殊规则无法安全计算时报告失败并保留原任务。沿用写锁和凌晨暂停时段。

- `搬家-地点-M.D`（亦支持 `搬家-地点-YYYY.M.D`）以末尾日期为搬家原点。无年份首次按北京时间当年解析并保存基准年份；标题日期变化才重算。「出门前三天」等一级阶段复用出行模板的相对天／周／月／年规则，所有层级后代均跟随所属一级阶段；原有时刻与重复规则保留，无日期任务补全天日期。完成状态保持不变。无日期标题只同步内容；无效日期拒绝排期。已按标题排期的整棵树排除普通轮换，避免后续排程覆盖。接入原有小时与完整重排入口。

- 模板间的 📌 专属规则：子任务标题末尾为 📌（忽略末尾空白）时，该关联组不在两份模板间互相覆盖或复制，另一边不存在也不报缺失；原任务保留。Checklist 中末尾为 📌 的条目不参加跨模板比较与复制，目标模板原有的 📌 条目及其勾选进度、ID 保留。普通条目继续双向同步；标记移除后重新参加同步。搬家模板自己的专属 checklist 仍可跟随同类「搬家-」实例，不能传到出门模板。标题日期排期规则不受 📌 影响。

- 阶段本身的 checklist 也参加同步：两份模板同名的一级阶段（如「出门前一天」）按阶段名关联，忽略末尾 🎒🧳📦 装箱标记；仅同步检查事项，不覆盖阶段名称、备注估时、日期或层级。首次接入时合并双方已有普通条目，保留各自 📌 条目与勾选进度；保存基准后跟随单边修改／可比较的较新修改。阶段标题末尾 📌 则跳过跨模板同步，同名多阶段拒绝猜配。搬家实例相同阶段的 checklist 一并跟随，沿用原阶段日期与完成状态。相对日期解析同样识别末尾装箱标记，例如「出门前三天📦」。
- 重排回读按字段语义验证：JSON 对象字段顺序、空备注／空列表的缺省表示、同一时刻的时区表示不算内容变化；检查事项文字、顺序、ID 和进度仍须一致。真实差异仍停止该规则且不保存同步基准，失败状态只展示字段名，不记录待办正文。
